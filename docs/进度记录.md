## 四之三、验收取证与缺陷修复（2026-09-17 晚）

### 取证怎么做的

`backend/scripts/capture_evidence.py`（约 950 行）——**Playwright 驱动本机 Edge**（`channel="msedge"`，不下载浏览器），
按验收动线真实登录、真实点按钮、真实提交作答，**边点边断言边截图**，落进 `docs/evidence/工单XX/`。
一条命令跑完全部三个工单：

```bash
cd backend && python scripts/capture_evidence.py            # 全跑
cd backend && python scripts/capture_evidence.py --stage learn-exam   # 只跑某一段
```

它的价值不在"省了手工截图"，而在**它会把人的"以为点到了"变成机器可核对的断言**——
下面 5 个缺陷里有 3 个是肉眼点一百遍也未必发现、但断言一跑就红的。

### 修掉的 5 个缺陷

| # | 缺陷 | 影响 | 位置 |
| --- | --- | --- | --- |
| a | **多选题渲染成单选控件** | 答案形如 `ABC`，单选控件**永远选不中第二个字母** → 学生必然被判错 → 错判写进画像、拉低掌握度、改推荐路径。**这是会污染演示数据的缺陷**（且演示时看起来"系统判错了"，最伤验收） | 前端 3 处：`Practice.vue`（练习 + 试卷）、`Mistakes.vue`（变式题） |
| b | **图片类文档引用回显 500** | `image_parser.py` 把 `rel_prefix` 当完整路径存，入库的是**目录** `kb/5`；回显时 `FileResponse` 打开一个目录 → 500 | `services/parsers/image_parser.py` + `api/kb.py` |
| c | **变式题再答错后反馈整块消失** | 再错会触发重新分析、换一批新变式题，刚作答那道被换掉 → **判分、正确答案、这道题的解析一起不见**，学生点完「提交」只看到题目变了，等于白答 | `Mistakes.vue` |
| d | **联动助教入口是断的** | `Chat.vue` 不读 `?q=` / `?conversation=`，三处入口（仪表盘 / 路径节点 / 错题详情）点过去**落在一个空会话上**。工单19 验收标准第 4 条要求的三条链路之一，实际不可用 | `Chat.vue` |
| e | `ElTag type=""` 触发 14 条 Vue 警告 | 不影响功能，但控制台噪音会掩盖真问题 | `CitationList.vue` |

> **a 的关键判断**：这不是"前端没做"，而是"前端做错了"。后端**本来就支持多选**（判分按集合比较），
> 且 `qtype` 字段**本来就在返回体里**——所以这是纯前端缺陷，修 3 个调用点即可，**没有改任何接口**。
> **b 的关键判断**：`parsers/__init__.py` 的约定与 `base.save_image_bytes` 的实现都写明"`rel_prefix` 是**目录**"，
> **是 `image_parser.py` 自己违反了约定**。所以修法是让它对齐约定，不是改约定。
> **顺带发现测试把 bug 当成了契约**——原用例恰好按"传完整路径"的方式调用解析器（正是线上 500 的调法），
> 已改写为目录约定，并补 2 条回归用例（正常回显 200、历史脏数据报 **404 而非 500**）。

## 八、已解决的坑（避免重复踩）

1. **`pytest.ini` 中文注释在中文 Windows 崩** —— iniconfig 按系统 GBK 读 .ini，报 `UnicodeDecodeError`。
   配置统一写在 `backend/pyproject.toml`（TOML 按 UTF-8 解析）。已写入 CLAUDE.md §9。
2. **`python_files` 必须含 `pytest_*.py`** —— CLAUDE.md 硬约束 3 规定的文件名不匹配 pytest 默认的 `test_*.py`，
   不配置会「no tests ran」。
3. **习题模板原先不要求 `score` 字段** —— 实测 23 道题分值全为 `None`，教师得手工补。
4. **试题模板手写「总分 100 分」但分项相加只有 90** —— 已改为由 `DEFAULT_EXERCISE_SPEC` / `DEFAULT_EXAM_SPEC`
   经 `_spec_line()` 生成题量与总分，文案与分值无法再脱节。上面 3、4 两条都有 `TestPromptSchema` 用例守着。
5. **`EventSource` 只支持 GET** —— 生成接口是 POST + JSON body，故前端用 `fetch` + `ReadableStream`
   手写 SSE 帧解析，同样逐块消费。理由写在 `frontend/src/api/lesson.js` 顶部注释。
6. **Python 读写文件一律显式 `encoding="utf-8"`** —— 连临时分析脚本也一样，否则中文 Windows 上默认 GBK 直接报错。
7. **重启后端要按 PID 杀** —— `taskkill` 按窗口标题过滤常常杀不掉，旧进程仍占 8000，
   新进程静默启动失败（`error while attempting to bind`），结果调试的是旧代码，白折腾一轮。
8. **numpy 2.x 与 conda 编译的 scipy/sklearn/pandas 不兼容**（工单18 期间修复）——
   `import sklearn` 直接 `ImportError: numpy.core.multiarray failed to import`，
   连 `sentence_transformers`、`transformers`（`generation.utils` 里 import sklearn）都被拖垮。
   修法：`pip install -U scipy scikit-learn pandas -i https://pypi.tuna.tsinghua.edu.cn/simple`
   （装 numpy 2 版轮子覆盖 conda 版，**不要降级 numpy**，很多新包已要求 numpy>=2）。
   副作用：`gensim 4.3.3` 声明 `numpy<2`，本就用不了，本项目不依赖它。
9. **本地 Embedding 不走 sentence-transformers** —— 依赖链长（sklearn/scipy/pandas），
   改为 `transformers` + `torch` 手写 CLS 池化 + L2 归一化，实测与官方实现数值一致（差异 3e-8）。
   代码在 `app/services/embedding.py::_embed_local`，切换只改 `.env` 的 `EMBEDDING_PROVIDER=local`。
10. **换 Embedding 模型必须重建向量库** —— 云端 bge-m3 是 1024 维、本地 bge-small 是 512 维，
    Chroma 的 collection 维度建库即固定。已加 `.embedding_signature.json` 签名文件：
    写入前拦截并给出「删 data/chroma 重新解析」的提示，召回侧自动降级为关键词召回。
11. **Vite 代理目标必须写 `127.0.0.1` 而不是 `localhost`**（工单18 期间修复）——
    Vite 监听 `[::1]:5173`，Node 把 `localhost` 解析到 IPv6 的 `::1`，
    而 uvicorn 默认只监听 IPv4 `127.0.0.1:8000`，结果前端所有 `/api` 请求 502。
12. **本机 shell 有系统代理**（`HTTP_PROXY=http://127.0.0.1:7897`）——
    用 curl 测本地端口会得到代理返回的 **502**，看着像服务挂了其实是没连上。
    本地自测加 `curl --noproxy '*'`，python 脚本用 `httpx.Client(trust_env=False)`。
13. **PyMuPDF 抽的表格/文本会带 HTML 实体**（`&amp;#45;` 之类）——
    解析器里统一 `unescape_entities()` 清洗；测试用例也据此断言。
14. **公式识别是保守启发式** —— 只把「无中文 + 含数学符号 + 运算符密度达标」的行判为公式块，
    纯 ASCII 公式（`y = wx + b`）按正文入库（仍可被检索到），宁可漏判不误判。
15. **判断后端跑的是不是最新代码，看 `/openapi.json` 而不是看进程在不在**（工单19 收工前实测踩到）——
    8000 端口明明 LISTENING，人也在 `curl /docs` 拿到 200，但那是**工单19 之前启动的旧进程**，
    `/api/learn/*` 一条都没有，前端页页 404。一条命令就能确认：
    `curl -s http://127.0.0.1:8000/openapi.json | python -c "import sys,json;print(len(json.load(sys.stdin)['paths']))"`
    （当前应为 **43**）。杀旧进程用 `taskkill //F //PID <PID>`，重启加 `--reload` 免得再来一次。
    ⚠️ **`--reload` 也不是万能的**：本轮改完 `kb.py` 后 `/api/kb/chunks/14/image` 仍返回 500，
    一度以为修错了；用进程内 `TestClient` 一跑得到的是正确的 **404**，才确认是**服务没真正重载**。
    结论：**怀疑"改了没生效"时，先用进程内 TestClient（或 pytest）验证代码本身，再去怀疑服务**。
16. **文件存在性判断别用 `exists()`，要用 `is_file()`**（缺陷 b 的次生坑）——
    `Path.exists()` 对**目录**也返回 True，于是 `FileResponse` 打开一个目录，
    在**发送响应时**才炸成 500（栈里看不到自己的代码，极难定位）。历史脏数据就靠 `is_file()` 兜住，报 404 而不是 500。
17. **Playwright 取证时的三个坑**（`capture_evidence.py`）：
    - **`channel="msedge"` 驱动本机已装的 Edge，不下载浏览器**（本机无 GPU，也无需 Chromium 全家桶）
    - **hash 路由下只变 query 的 `page.goto` 是空操作**——路径部分相同就不会触发组件重挂载，
      `onMounted` 不跑、参数读不到。脚本里在 `goto` 后补一次 `page.reload()`（判断"路径相同、query 不同"）
    - **`el-input type="textarea"` 的 DOM 选择器是 `.chat-input textarea` 而不是 `input`** ——
      写 `.chat-input input` 会匹配不到任何元素，于是"输入框已带入"这条断言永远为假，而截图看起来"只是没填"
18. **`v-show` 的面板全都留在 DOM 里** —— 学习路径页每个节点都挂了一个 `RelatedPanel`（用 `v-show` 收起），
    `.related-panel .first` 会抓到**别的折叠节点**的面板。要么用 `.nth(节点下标)` 限定，要么改成 `v-if`。
19. **单跑一个 stage 会重置截图序号** —— `--stage learn-related-chat` 会让工单19 里出现第二个 `01-*.png`。
    要一套连续编号的存证，就**先清空 `docs/evidence/工单XX/` 再跑完整的一轮**。

21. **备份文件会"腐坏"，而且腐坏得很安静**（本轮真踩到，用户当场撞上）——
    `edu_agent.db.bak-20260917` 是**图片 bug 修复之前**存的，冻结的正是当时的错误数据

    能重建就重建一个验证过的干净备份（重建法：拿旧备份只改那一格，再和"已修复的线上库"**逐表逐行对比**，
    21 张表零差异才算数），并**把旧的标注成"别用"**而不是删掉。
22. **流式切句的四个边界**（`audio/sentenceSplitter.js`，阶段二）—— 大模型是**一个 delta 一个 delta** 吐字的，
    切句必须容忍"半个句子"的状态：小数点 `3.14`、缩写 `etc.` 不能切；`……`/`！！！` 要等连完再切（否则切出一堆单字句）；
    `他说："你好。"然后走了。` 要在**引号闭合后**再切（否则引号被甩到下一句开头）；
    代码围栏 ` ``` ` **可能跨多个 delta 到达** —— 必须用状态机，不能"看见 ``` 就反转一个布尔量"。
23. **流式朗读的泵不能拿"本轮已有泵在跑"当防重入判据**（阶段二，最隐蔽的一个）——
    大模型**一阵一阵**吐字：一波句子播完、队列暂时空了，泵就退出了；等下一波 delta 到达时，
    若判据仍是"本轮已有泵在跑"，新句子会被**无声丢弃**——表现为**只念了开头三五个字就再也没声**，
    而日志、网络、控制台全都干干净净。正确做法：布尔量 + 世代计数器（`generation`）双管，
    被换代打断的旧泵在 `finally` 里**不清理**标志，避免误清新泵。真踩过，且极难从表象看出来。
24. **HTTP 400 不等于"服务挂了"**（阶段二）—— 表格行/纯符号送进 TTS，后端正当地回 400 "无可朗读内容"。
    前端若把它计入"连续失败"，一篇回答里出现 3 个表格行就会触发熔断，**后半篇全不念了**。
    处理：`speak()` 把 HTTP 状态带出来，400 当**正常跳过**；前端另在切句侧先丢弃 `|` 开头的行（省掉白跑的往返）。
25. **音量增益系数别调大**（阶段二）—— RMS × 6 时峰值长期顶在 1.0，嘴一直是全张的，反而没有表情。
    实测取 **3.5**（峰值 0.85~0.94）才有开合变化。平滑要**快开慢合**（0.5 / 0.15），对称会明显抖动。
26. **二次贝塞尔曲线的实际视觉高度只有控制点偏移量的一半**（阶段二）—— 起点终点同高时，
    曲线中点 = 起点 + 控制点偏移/2，所以 `h` 的系数要按"视觉高度 ≈ h/2"来定。
    原先 `open*15` 全张也才 7px，在脸上几乎看不出张嘴，**是看截图才发现的**；改为 `open*30`。
27. **口型绝不能进 Vue 响应式**（阶段二）—— 问答页每次 delta 都全量重跑 `marked.parse()`，已是热路径；
    音量再逐帧触发重渲染会直接卡死。做法是 rAF 直写 SVG 的 `d` 属性，只有 `speaking`（低频）走响应式。
28. **`decodeAudioData` 不可取消**（阶段二）—— `stop()` 之后在途的解码回调仍会回来。
    用世代计数器让所有过期回调失效，否则会有**残留声音**。另：`AudioContext` 必须在**用户手势的同步栈里**
    创建/恢复（`handleSend` 内、任何 `await` 之前），否则 autoplay 策略直接挂起音频。
29. **取证脚本自身也会撒谎**（阶段二，本轮 14 条断言调了三轮才稳）——三个坑都不是产品缺陷：
    - **「正在讲解」不等于「流还在跑」**：边生成边念会让尾句在流收尾后继续播，
      于是"等正在讲解 → 点停止生成"会**白等 20 秒报超时**（按钮早已变回"发送"）。
      正解：先等按钮出现（证明流在跑），循环条件里一并盯按钮在不在。
    - **采样循环退出 ≠ 还在发声**：循环退出往往正是最后一句念完的那一刻，
      此时截到的是"文案已转待命、口型停在上一帧"的**自相矛盾画面**（口型走 rAF 直写、文案走 Vue 微任务，
      收尾时天然差一帧）。正解：采到张嘴帧**当场**按快门，不要等循环结束再截。
    - **别用绝对句数当判据**（如 `played >= 3`）：能念几句取决于大模型这次写了什么，
      表格占比高的回答只剩两句可念，会**偶发空等 60 秒**。正解：判「≥ 2」——第 2 句必须等第 1 句播完才开播，
      已足以证明串行推流。
