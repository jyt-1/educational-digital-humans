## 一、这是什么

### 1.1 一句话定位

**面向高职院校的"AI 教学大脑" + 数字人交互层**：把教师备课、学生答疑、个性化学习推荐三件事打通，外面套一个能听会说的数字人形象。

它不是"又一个 AI 聊天工具"，差别在三处：

| 差异点 | 普通 AI 聊天工具 | 本平台 |
| --- | --- | --- |
| 回答依据 | 模型自己的记忆 | **检索校本知识库**，答案带 `[1][2]` 引用角标，可点回原文/图片/表格 |
| 是否懂"我校学生" | 不懂 | 有**知识点图谱 + 学生画像**，知道每个人弱在哪、下一步该学什么 |
| 产出物 | 一段文字 | **可编辑、可版本回溯、可导出 docx/pptx 的教学材料**；答题数据回流成学情 |

### 1.2 解决的三个真痛点

1. **教师重复劳动**：做一门课的教学材料要 2~3 天，且年年重做 → 现在是**填几个参数、几十秒流式生成**教案/课件/习题/案例/试题五类内容，再在线改、导出。
2. **学生问题无处问**：老师不可能 7×24 在线；校本资料散在教师个人电脑里 → 现在是**带引用、可追溯到第几页**的流式答疑，还支持**语音提问**。
3. **学生不知道"我错在哪、该学什么"**：错题只记答案不理解原因 → 现在是**画像 + 可解释学习路径 + 错题 AI 剖析 + 同知识点变式题**的闭环。

### 1.3 技术底座（决定成本与部署方式）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + Element Plus + ECharts | PC 浏览器访问，无需装客户端 |
| 后端 | Python + FastAPI + SQLAlchemy + SQLite | 开发/试点期 SQLite 足够，生产换 PostgreSQL/MySQL |
| 向量库 | ChromaDB（本地持久化） | 检索不走第三方，数据留在校内 |
| 大模型 | 云端 OpenAI 兼容接口（当前 DeepSeek chat） | 生成、分析、判分全靠它 |
| 向量化 / 重排 | 本地兜底模型 + 可选云端 API | 无显卡也能跑（本地 bge-small-zh-v1.5，CPU） |
| 语音合成 | Edge-TTS（微软在线服务，免费、无 Key） | 8 个中文音色，结果落盘缓存，重复语句断网也能播 |
| 语音识别 | 浏览器 Web Speech API | 免费、免部署；仅 Chrome / Edge 支持 |
| 数字人形象 | 写实照片 + 音量驱动口型（7 个形象可选） | **零 GPU、零素材成本、离线可用** |

> **部署硬门槛只有一条：不需要独立显卡。** 所有重活儿都在云上或浏览器里，本地只跑业务逻辑。

## 二、里面都有啥（功能清单）

### 2.1 功能全景

侧边栏三个一级模块、八个二级页面，外加挂在智能问答页上的数字人：

```
智能备课（教师）        智能助教（师生）        个性化学习（学生）
├ 内容生成              ├ 智能问答 ★数字人       ├ 学习仪表盘
└ 我的备课              ├ 知识库               ├ 学习路径
   （列表/编辑/版本/导出） └ 检索调试            ├ 练习与试卷
                                              └ 错题本
```

### 2.2 模块一 · 智能备课（教师用）

- **五类内容一次生成**：教案 / 课件 / 习题 / 案例 / 试题（月考试题）；填学科、课程名、章节、知识点、难度、教学目标即可。
- **流式生成**：一边生成一边上屏，不用干等；随时可中断。
- **在线编辑**：教案/案例是 Markdown 编辑+预览，课件按页编辑（标题+要点+**讲稿备注**），习题/试题逐题结构化编辑（题干、选项、答案、解析）。
- **资料引用**：可检索校本知识库，把资源一键插进正文并自动标注来源。
- **版本管理**：每次保存自动生成版本快照，可看历史、**可回滚**（回滚不删历史，是追加一个新版本）。
- **导出**：教案/习题/试题 → **docx**，课件 → **pptx**，中文文件名不乱码。

> 课件每一页的「备注（notes）」字段很关键——它是后面"数字人试讲"的天然讲稿钩子。

### 2.3 模块二 · 智能助教（师生都用，核心模块）

**知识库**
- 支持 **PDF / Word / PPT / Excel / 图片** 五类文档统一上传解析入库。
- **多模态专门处理**：表格转 Markdown 存储、图片单独成块记录路径（引用时可原图回显）、公式保留原文位置与上下文。
- **双库隔离**：`public`（全校共享，仅教师/管理员可写）与 `private`（按用户隔离，各自私有）。
- 上传后异步解析，界面显示解析状态；可删除、可"重新解析"重建切块与向量。

**智能问答（数字人挂载点）**
- **混合检索**：向量召回 + 关键词召回，融合后可选重排，取最相关的几条。
- **带引用的流式回答**：答案里嵌 `[1][2]` 角标，点角标自动展开右侧引用抽屉并高亮对应来源卡片；引用可点开看原文、图片、表格。
- **多轮对话**：携带最近几轮历史；会话可列表、可回溯、可删除。
- **语音输入**：点麦克风直接说话，识别完自动提问（详见 2.5）。
- **检索调试页**：给实施/教研人员看的"透明窗口"，能直接看检索命中了哪些块、分数多少。

### 2.4 模块三 · 个性化学习（学生用）

- **知识点图谱**：内置"人工智能导论"40+ 知识点及先修关系（如 矩阵运算 → 神经网络 → 反向传播 → 梯度下降）。
- **学生画像**：按知识点算掌握度，带**时间衰减**（7 天内权重 1.0 / 30 天内 0.7 / 更早 0.4）——反映"现在"的水平而不是历史平均。支持**导入历史成绩**冷启动（模板只含知识点/得分/满分三列，可整批撤销）。
- **学习路径推荐**：定位掌握度不足的薄弱点，**沿图谱上溯到最上游的先修薄弱点**，给出学习顺序 + **可解释理由**（"建议先学 A，因为 A 未掌握且是 B 的前置知识点"）。
- **自适应练习**：答对反馈、难度自适（连对 3 题升档、答错降档）。
- **试卷模式**：抽整套试题一次作答，交卷后统一判分出分并入画像（考试不调难度档——"考试是测量、练习是训练"）。
- **AIGC 错题本**：答错自动触发 AI 分析，输出【深入浅出的解析 + 错误原因诊断（对标该知识点的常见误区）+ 2~3 道同知识点变式题带答案】；变式题再答、再错重新分析。
- **联动助教问题库**：错题详情、仪表盘"今日任务"、学习路径每个节点，三处给出【相关提问 / 关联学习资料 / 同知识点练习题】。
- **知识点治理（教师）**：题库汇入、别名归并、未归类清点——保证图谱干净、可解释。

### 2.5 数字人形象层（这是"看得见"的那个部分）

| 能力 | 现状 |
| --- | --- |
| 形象库 | **7 个可选**：6 个写实教师照片（晓雯/苏青/周慧/林悦/陈远/吴谦，男女各 3）+ 1 个 Live2D 二次元形象（小满） |
| 发声 | Edge-TTS，8 个中文音色，**换形象自动配对对应音色**（女形象→女声、男形象→男声） |
| 口型 | **真·音量驱动**：音频播放时的实时音量驱动张嘴幅度 + 下颌自然下移，**不是按固定节奏播的假动画** |
| 表情动作 | 呼吸起伏、随机眨眼（眼睑覆层，物理正确）、说话时头部微摆、聆听时慢速侧倾 |
| 聆听 | 点麦克风 → 胶囊状态变"倾听中" → 说完自动发问 |
| 状态标签 | 悬浮胶囊：待命中 / 倾听中 / 思考中 / 回复中（带呼吸圆点） |
| 声波 | 24 根音浪条，高度实时跟随音量 |
| 朗读控制 | 一键静音/恢复；音色下拉切换 |
| 舞台 | 沉浸式布局：左侧 25% 会话与设置，右侧 75% 数字人舞台 + 悬浮输入框 + 引用抽屉 |

**切句机制**：一篇回答不等生成完就开始念第一句（边生成边念），表格类内容跳过不念（念表格噪声大于信息）。

## 三、给谁用（角色与场景）

### 3.1 四个角色

| 角色 | 系统标识 | 他关心什么 | 主要用哪几个页面 |
| --- | --- | --- | --- |
| **教师** | `teacher` | 少干重复活、知道班里学生弱在哪 | 智能备课全部 + 知识库 + 智能问答 + 学习路径页的「知识点治理」 |
| **学生** | `student` | 有人随时答疑、知道下一步学什么、知道错在哪 | 学习仪表盘 / 学习路径 / 练习与试卷 / 错题本 + 智能问答（语音） |
| **教务 / 信息中心** | `admin` | 数据沉淀、账号管理、系统能跑 | 公共知识库维护（本期仅建角色，未做独立后台） |
| **就业指导教师** | — | 学生面试表现、针对性辅导 | ⏸️ 对应"面试 AI 复盘"功能，**本期不做**（设计已存档） |

### 3.2 典型动线

**教师的一天**
```
登录 → 智能备课·内容生成：填"人工智能导论 / 反向传播 / 中等" → 生成教案+课件+试题
     → 在线改课件某一页 → 保存（自动存版本）→ 导出 pptx 上课
     → 把课程资料上传到知识库（公共库）
     → 课上学生问不会的，让学生自己去智能问答问
     → 课后打开学习路径页，看「知识点治理」把未归类题目归并到正确知识点
```

**学生的一天**
```
登录 → 学习仪表盘：掌握度雷达图 + 今日任务（链式法则）
     → 学习路径：3 步时间线，每步都写了"为什么先学这个"
     → 练习与试卷：答题 → 即时反馈；或切"试卷模式"整套作答交卷出分
     → 答错了 → 错题本自动产生 → 点「生成 AI 分析」→ 看解析+错因+变式题
     → 还是不懂 → 切到智能问答 → 点麦克风直接说话问，数字人念给你听
     → 答题数据回流 → 画像更新 → 路径自动调整
```

### 3.3 一个班/一所学校怎么落地

- **试点规模**：单院校，教师 50~200 人、学生 2000~5000 人，峰值问答并发 < 50 QPS，SQLite 够用。
- **终端**：PC 浏览器为主（实训室/办公室/宿舍），本期不做移动端适配，仅保证基本响应式。
- **网络**：需能访问公网 API（大模型、语音合成）；本地不加载大模型权重。

## 四、C 端还是 B 端

### 4.1 结论

> **B 端产品，B2B2C 形态。**
>
> 采购与付费方是**院校（教务处 / 二级学院 / 信息中心）**；使用者是**教师（B 端角色）和它的学生（C 端体验）**；学生是"被服务方"，不是"付款方"。

一句话概括：**卖给学校，用给学生。** 学生端要有 C 端的产品体验（零学习成本、7×24、能语音对话），但商业模式和部署形态是彻头彻尾的 B 端。

### 4.2 判定依据

| 维度 | 事实 | 指向 |
| --- | --- | --- |
| 谁掏钱 | 学校预算 / 教务专项 / 信息化建设经费 | **B 端** |
| 谁做决策 | 教务处、信息中心、二级学院——要过评审、要能私有化部署 | **B 端** |
| 数据资产 | 校本知识库、题库、学情画像、试卷——都是**机构资产**，不能挂在个人账号下 | **B 端** |
| 部署要求 | 数据不出校（私有化 / 校内服务器） | **B 端** |
| 价值主张 | 对校方：降低备课成本、提升学情可视化、就业环节可量化 | **B 端** |
| 使用者体验 | 学生端要像 C 端 App 一样好用：语音提问、零门槛、随问随答 | 需 **C 端体验** |
| 权限模型 | 教师/学生分权、公共库与私有库隔离、学生数据按人隔离 | **B 端** |

### 4.3 为什么不直接做纯 C 端

1. **付费意愿撑不住**：学生个人为"答疑"付费的意愿很低，而免费的通用大模型（DeepSeek/豆包/Kimi）已经能满足大部分"问一个问题"的需求。
2. **没有壁垒**：公开知识谁都能问，真正难复制的是**校本资料 + 学情闭环 + 教师工作流**——这三样只有机构才拿得出来。
3. **合规成本高**：涉及未成年人/在校学生数据、校内资料版权，个人开发者身份做 C 端很难过合规关；机构主体天然合适。
4. **获客成本高**：C 端要买流量，B 端靠院校渠道和标杆案例复制。
5. **产品重心对不上**：C 端比的是"模型多聪明"，B 端比的是"能不能融进教学流程、能不能出教学材料"——本平台的重心（备课版本管理、导出 docx/pptx、知识点治理、试卷判分）全在 B 端。

### 4.4 商业化路径建议

| 档位 | 形态 | 适合对象 |
| --- | --- | --- |
| ① SaaS 订阅 | 按校年费，云端托管 | 中小院校试用起步，门槛低 |
| ② 私有化部署 | 一次性授权 + 年度维保 | 数据敏感、要求数据不出校的院校（**主推**） |
| ③ 按坐席/规模阶梯 | 按教师账号数或活跃学生数计价 | 规模差异大的院校，便于扩展 |
| ④ 专业共建 / 定制 | 结合专业（如人工智能、数字媒体）定制知识库与课程包 | 有特色专业建设需求的院校 |

**目标客户优先级**：高职院校（**首选**——就业导向、实训痛点明确、信息化预算相对灵活）→ 中职 → 企业培训（内容审核更松、付费能力更强）→ K12（需适配教材版本、内容审核最严，放最后）。

**延伸可能**：同一套内核可以另做一个 C 端自学版（如考研/考证/编程自学），但那是**第二条产品线**，不是本平台的定位。

## 五、怎么操作（上手指南）

### 5.1 环境要求

- Windows 10/11（或 Linux/macOS）
- Python 3.11+（开发机用 Anaconda 的 3.12）
- Node.js 18+（开发机用 22.x）
- **无需独立显卡**
- 需能访问公网（大模型 API + 语音合成）
- 浏览器：**Chrome 或 Edge**（语音识别只在这两个里可用）

### 5.2 首次安装

```bash
# 后端依赖
cd C:/Users/23772/sx/Education-agent/backend
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 前端依赖
cd C:/Users/23772/sx/Education-agent/frontend
npm install --registry=https://registry.npmmirror.com

# 配置：复制 .env.example 为 .env，填大模型 Key
# LLM_API_KEY / LLM_BASE_URL / LLM_MODEL 必填
```

### 5.3 启动（两个终端，都别关）

```bash
# 终端① 后端
cd C:/Users/23772/sx/Education-agent/backend
D:/anaconda3/python.exe -m uvicorn app.main:app --reload --port 8000

# 终端② 前端
cd C:/Users/23772/sx/Education-agent/frontend
npm run dev
```

浏览器打开 **`http://localhost:5173`**（用 `localhost`，不要用 `127.0.0.1`）。

**确认后端是新的**：访问 `http://localhost:8000/docs`，或执行下面这条，返回 **46** 才算正常：


登录页也可以直接注册新账号（注册时选角色）。会话有效期 7 天。

### 5.5 教师操作

1. **生成内容**：左侧「智能备课 → 内容生成」→ 填学科/课程/章节/知识点/难度/教学目标 → 勾选内容类型（教案/课件/习题/案例/试题，可多选）→ 点生成，看着它流式写出来。
2. **在线编辑与保存**：「智能备课 → 我的备课」→ 点某条记录进入编辑页；改完点保存，**系统自动存一个版本**。
3. **版本回滚**：编辑页左侧版本时间线 → 选历史版本 → 回滚（**不会删掉历史**，是追加一个新版本）。
4. **导出**：编辑页点导出 → 教案/习题/试题得到 `.docx`，课件得到 `.pptx`。
5. **建知识库**：「智能助教 → 知识库」→ 拖拽上传 PDF/Word/PPT/Excel/图片 → 选 `public`（公共库，需教师身份）或 `private` → 等解析完成（状态会变）。
6. **知识点治理**：「个性化学习 → 学习路径」右上角，把"未归类"的题目归并到正确知识点。**这一步决定雷达图和路径好不好看**。

### 5.6 学生操作

1. **建画像**：「学习仪表盘」→ 用「导入历史成绩」上传填写好的模板（知识点/得分/满分三列），或直接做练习从零积累。
2. **看短板**：「学习路径」→ 时间线逐步给出"先学什么、为什么"。
3. **刷题**：「练习与试卷」→ 默认练习模式（答完即时反馈）；切「试卷模式」抽整套试题作答 → 交卷 → 统一出分并入画像。
   - 多选题是**方框**，单选是**圆点**。
   - 连续答对 3 题自动升难度档。
4. **错题本**：「错题本」→ 选一道错题 → 点「生成 AI 分析」→ 约 6 秒后出现解析 + 错因诊断 + 变式题 → 做变式题巩固。
5. **找资料**：错题详情侧栏、仪表盘"今日任务"、路径页每个节点，三处都有【相关提问 / 学习资料 / 练习题】入口。

### 5.7 数字人怎么用

**入口**：「智能助教 → 智能问答」——右侧 75% 那一栏就是数字人舞台。

| 想做什么 | 怎么做 |
| --- | --- |
| 换形象 | 舞台右上角「形象设置」→ 7 个形象点一下即换（写实 6 个 + Live2D 1 个），音色自动配对 |
| 换声音 | 同面板里的音色下拉（8 个中文音色） |
| 静音 / 恢复 | 右上角「🔊 朗读中 / 🔇 已静音」开关 |
| 语音提问 | 点输入框旁的麦克风 → 状态变「倾听中」→ 说完自动发送（首次需允许麦克风权限） |

### 5.8 十分钟演示脚本（照着念即可）

1. **（1 分）教师登录** → 智能备课·内容生成：填"人工智能导论 / 反向传播 / 中等"，勾教案+课件+试题 → 生成（讲"流式，边生成边出"）。
2. **（1 分）**进入「我的备课」→ 打开生成的课件 → 改一页 → 保存 → 展示版本时间线 → 导出 pptx（下载打开看一眼）。
3. **（1 分）**上传一份课程 PDF 到知识库 → 展示解析状态与切块。
4. **（2 分）**切「智能问答」：提问"表格里 Adam 优化器适合什么场景？"→ 数字人**边生成边念**、嘴型随声音开合、眼睛在眨、头部微摆；点 `[1]` 角标展开引用回到原文；换一个形象（如"陈远"）→ 音色自动变男声；点麦克风用语音问一句。
5. **（2 分）学生登录** → 学习仪表盘：雷达图 + 今日任务；学习路径：3 步 + 每步的"为什么"。
6. **（2 分）**练习页答对一题（即时反馈）→ 故意答错一题 → 切试卷模式交卷出分。
7. **（1 分）**错题本 → 生成 AI 分析 → 解析 + 错因 + 变式题。

### 5.9 常见问题排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 数字人不说话 | ① 看「朗读」开关是否被静音（再点一下恢复）；② **Edge-TTS 走微软在线服务，必须先确认能联网**——断网不会报错，只是静默不朗读（属设计好的降级行为） |
| 点麦克风没反应 | 必须用 **Chrome / Edge**；首次点要允许麦克风权限。Firefox 等不支持，会提示换浏览器 |
| 学生账号点「我的备课」报 403 | 已知小瑕疵：该接口是教师专属，但侧边栏没按角色隐藏。不影响其他功能 |
| 引用里的图片一片空白 | 用错备份还原了。日常还原一律用 `data/edu_agent.db.bak-demo` |
| 练习页提示"题库尚未同步" | 教师先跑一次题库汇入（`POST /api/learn/kp/sync?target=questions`），演示库已灌好，正常无需重跑 |
| 某个知识点下没有题 | 题库按知识点分布不均属正常；界面会显示空态提示「请让教师重新同步题库」 |
| 端口被占用启不来 | `netstat -ano \| findstr :8000` 找到 PID 后杀掉；Windows 终端乱码先 `chcp 65001` |
| 想回到干净的演示状态 | 停后端 → `cp data/edu_agent.db.bak-demo data/edu_agent.db` → 重启，没有别的步骤 |

### 6.1 阶段三 · 云端数字人接入（现在做到哪一步、真要接怎么做）

#### 6.1.1 现在手里有什么

可替换点已经就位，问答页没有任何硬编码：

| 可替换点 | 位置 | 现状 |
| --- | --- | --- |
| 形象驱动 provider | `frontend/src/avatar/provider.js` | 具名实现 + 静态注册表 + `pickAvatarProvider()` 查找，未知值**回退 photo 并告警**（`.env` 写错不会白屏）。svg-face 卡通脸已于 2026-09-18 退役，现有 photo / live2d 两档，渲染分派统一走 `pickRender()` |
| 语音合成 provider | `backend/app/services/tts.py` | `_PROVIDERS = ("edge",)` + settings 字符串开关 + if/else 分派 |
| 开关 | `.env` | `AVATAR_PROVIDER`、`TTS_PROVIDER` |

**但"只改配置"要分接入形态看**，这是最容易被一句话糊弄过去的地方：

| 形态 | 云端返回什么 | "只改配置"成立吗 |
| --- | --- | --- |
| **形态 B** | 音频 + 口型参数（形象仍由本地渲染） | ✅ 成立：加一个 provider 实现 + 改 `.env`，问答页与舞台不动 |
| **形态 A** | **视频流**（形象与口型都在云端渲染完） | ❌ **不成立**：前端渲染层要换成视频播放器 |

**实测结论（2026-09 查证）**：讯飞"超拟人数字人交互"与腾讯云"交互数智人"**都是形态 A**——握手成功后返回的是 `stream_url`（xrtc / WebRTC 推流地址），形象、口型、表情全在云端算好推给你。这一点在 `provider.js` 的注释里其实已经预判到了（"届时云端 SDK 多半自带渲染容器，需要给契约补一个可选的 `mount(container)`——那是阶段三的扩展点，本期不预先实现"）。

**形态 A 下必须额外改的四处**：

1. **前端新增渲染分支**：`render` 标记加一个 `'cloud-video'`，把 `<img>` / `<canvas>` 换成视频播放器（xrtc SDK 或原生 WebRTC）。
2. **本地口型管线必须停用**：云端视频自带口型，若本地 TTS 还在念同一段文本 → **双声**。这是接入时最容易翻车的点。
3. **声波可视化改取数源**：24 根音浪条原本分析本地播放的音频，改成分析视频流的音轨。
4. **后端加起流/停流接口**：管会话生命周期与配额（WebSocket 或 HTTP 握手），别把 `stream_url` 直接扔给前端裸奔。

#### 6.1.2 采购到手后的五步接入

1. **拿凭证与 Runbook**：APPID / APIKey / APISecret、已授权的形象 ID（`avatar_id`）、可用音色（`vcn`）。
2. **准备形象**：直接用供应商形象库最省事；走**形象克隆**则需录 3~30 分钟高清素材 + 过合规审核，**要预留排队周期**。
3. **后端新增 provider**：`_PROVIDERS` 登记 `cloud` + 实现 `_synthesize_cloud()`；若走形态 A，另加起流/停流接口。
4. **前端加渲染分支与开关**：`AVATAR_PROVIDER=cloud` / `TTS_PROVIDER=cloud`；未知值仍回退本地实现。
5. **灰度 + 兜底**：**保留本地 provider 做降级**——云端超时、配额耗尽、断网时自动回落 talking-photo，并做一次断网演练。教育场景里"演示当天云端挂了"是不可接受的。

#### 6.1.3 商务采购要问的八件事

照这个清单问，能省一轮来回：

1. **计费口径**：按**并发路数 × 月**，还是按**分钟 / 字数**？（这一个问题决定整个成本模型）
2. **并发上限与超限策略**：超了是排队、报错，还是可自动扩容？
3. **延迟**：首次握手 + 稳态延迟的 SLA 数字（要数字，不要"很快"）。
4. **TTS 是否含在内**，还是另计？
5. **形象授权**：形象库是否含商用授权？克隆的素材要求、审核周期、**肖像授权书归谁**？
6. **数据合规**：音频与文本是否出境、是否用于模型训练、留存多久？（写进合同）
7. **私有化部署**是否可谈、报价区间。
8. **试用额度**：讯飞"超拟人数字人交互"有免费试用包（企业档 10 小时 / 90 天 / 并发 1）——**够做一次 PoC 验证延迟与观感**，先试再买。

#### 6.1.4 成本量级提醒（2026-09 公开价，以商务报价为准）

| 形态 | 参考价 | 换算 |
| --- | --- | --- |
| 实时交互 · 并发计费 | 腾讯云国际站 2D 小样本 500 美元/月/路；国内站"交互数智人"特惠体验包 140 元/天 | 单路约 **3.6k~4.2k 元/月** |
| 实时交互 · 并发计费 | 讯飞虚拟人企业版约 5749 元/月/单路（第三方渠道价，**需向商务核实**） | 约 **5.7k 元/月/路** |
| 视频生成 · 按分钟（离线播报） | 腾讯云 20 元/分钟；讯飞约 9.9 元/分钟 | 10 分钟课件视频 ≈ **100~200 元** |

#### 6.1.5 结论与建议打法

**按并发计费的实时数字人不适合全校铺开**——按 3.6k~5.7k 元/月/路算，20 路并发就是 **7~11 万元/月**，而院校的预算量级撑不住这种持续性支出。

合理打法是分档，而不是整体替换：

- **主力保持本地 talking-photo**：零边际成本，已经覆盖"数字人会说话"的核心需求（音量驱动口型、眨眼、聆听态、语音提问都在）。
- **"数字人讲课件"走离线视频生成**：按分钟计费、一次生成反复播放，成本可控，且不占并发。
- **实时交互只买 1~2 路**：用于公开课、招生演示这类"门面场景"。
- **云端数字人定位为高端可选档**：定价上做成加购项，而不是默认可选。
